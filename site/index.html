What if you weren't?

Describe a real situation. WHAT IF extracts what is actually known, generates alternative trajectories, and lets you walk the possibility graph that survives.

An LLM possibility is not a reality. The model proposes; the application validates, scores and visualises. Nothing generated is presented as a prediction.

How it works

A paragraph becomes a walkable graph

The model is asked only for what a model is good at. Everything an ordinary algorithm can decide is decided by ordinary code.

  1. 1 Extract Free text becomes a validated RealityState — events, constraints, goals, and explicit gaps.
  2. 2 Route & fork One of nine domain modules supplies the causal variables and hard rules; decision points are detected and ranked.
  3. 3 Project Candidates become effects with a direction, magnitude and causal order, plus a structured state_delta.
  4. 4 Verify & revise Deterministic constraint checks, then an adversarial critic. Failures regenerate — bounded at two iterations.
  5. 5 Rank Survivors are scored, deduplicated and beam-pruned into an acyclic graph.
  6. 6 Explore Every outcome stores its resulting world, so any node can be forked again from that world.

Architecture

A bounded revise loop

The part a linear pipeline could not express: critic verdicts and constraint violations feed back into a targeted regeneration of only the failing branches.

The revise edge re-enters at generate_consequences, so passing branches keep the consequences and reviews they already have — a repair costs one LLM call per broken branch, not a full resample.

A hard constraint is never negotiable. When the iteration budget is spent, branches the critic merely disliked are admitted. Branches breaching a hard constraint are rejected. A constraint is not a preference.

Each node knows its world

A node can only be forked again if it knows which world it inhabits — otherwise the children of Accept the offer reason from the original reality and contradict the choice already made. So every outcome persists its resulting_state, depth and path_labels.

Exploring is cheap

Expansion is idempotent — a node with children returns them without an LLM call — and depth-guarded. compare runs no LLM at all: it diffs two branches' effects and world states deterministically.

Reliability

Every failure has a defined landing

The engine talks to a third-party model, sometimes behind a third-party proxy. OpenRouter, OpenAI and Anthropic share one HTTP adapter, so everything below holds for all three — only the wire format differs.

The failure that looks like success. OpenRouter fronts other providers, so an upstream failure can arrive as HTTP 200 with the real status nested in the body: {"error": {"code": 429}}. Retry logic that only reads response.status_code misses these — the request "succeeded", the payload fails to parse, and the caller sees a schema error instead of a rate limit that would have cleared on the next attempt. The body is inspected, not just the status line.

Transient faults back off

429 / 502 / 503 / 504, network errors, and in-body error codes retry on an exponential ladder — 2s, 4s, 8s… capped at 30s — with 25% jitter, so per-branch calls do not retry in lockstep and rate-limit themselves again. A Retry-After header wins, up to a 120s ceiling.

Schema errors don't sleep

Malformed JSON is repaired by feeding the validation error back to the model, with no backoff — a schema error is the model's fault, not the server's. Still invalid after repair, it is dropped before persistence; malformed output never reaches the database.

Demo data announces itself

In mock mode every response carries "mock": true and the UI renders a banner. A deploy that forgets to set a live LLM_PROVIDER cannot quietly serve fixtures at HTTP 200; an unknown provider is refused with 503.

Failures leave a trace

Every error path persists its llm_executions row before raising — the session is rolled back when a request raises, so a row that is only flushed is silently discarded. Retries, latency and tokens are all counted there.

Measurement

Quality is measured, not asserted

Unit tests running against a mock provider prove the plumbing works, but only ever re-read the fixture they were seeded with. Reasoning quality is scored in one place: the eval harness, against a live model.

Run it

Quick start

Docker Compose brings up the database, API and frontend. Migrations run on API start. 

git clone https://github.com/Ansarafsar/what-if.git
cd what-if
cp .env.example .env      # set LLM_PROVIDER (openrouter|openai|anthropic) + that key
docker compose up --build

Frontend on :3000, API on :8000, Swagger at /docs. Without a key the stack runs on canned demo data — and says so on every response.
